# 40. Specs for the thin items, part 1: the frame budget, the gig and the desk

**Written 2026-11-01** (the owner's split, adopted that day) for the ids the Order of work names that had no item text, check or number, so that Antigravity can take them. Part 2 (sound and beat, many plates, the fluids) is [`41-specs-sound-plates-fluids.md`](41-specs-sound-plates-fluids.md).

**How to read an entry.** `id (lane, size)`, then what is wrong or missing with the number that shows it, what to build and where, **Pass:** the number the change must reach, **Check:** the `npm run` script that prints it, and **Phone:** what the phone gets in the same PR. A figure marked *(read)* was counted from the code and is to be re-measured by the first run; a figure marked *(measured)* is a printed number from an earlier PR; a figure marked *(bar proposed)* is the bar this entry asks for, to be pinned by the person who writes the check against the first measured run, not by the builder. **A check marked *owed* does not exist yet or is not red on main: Claude writes it first, shown failing on main, and the builder never writes or loosens one** (`docs/handoff.md`). Where an id already has text elsewhere, the entry says where and adds only what was missing (a number, a check, a phone line).

The one-line index at the end of part 2 maps every id of the Order of work that is not a section number to the file that holds its text.

## The frame budget (Wave 4, lane C, M or S each)

Measure every item with `npm run stages` (the step's time by stage, alternate pairs, never one run each: its header says why) and `npm run encode` (dispatches, writes and bytes a step), at 512² on a thin gap, and quote the printed lines before and after in the commit. The home of H2c-1 to H2c-11 is `docs/webgpu-plan.md` "H2c", counted from the code on 2026-09-28; the list there is numbered 1 to 11 and these ids follow it: H2c-1 coarse levels in one workgroup, H2c-2 the warm start, H2c-3 `mgZero`, H2c-4 and H2c-11 shipped, H2c-5 first-order velocity, H2c-6 no aux target, H2c-7 the readback ring, H2c-8 air only where there are bubbles, H2c-9 pack after a step, H2c-10 grids a multiple of 32 (shipped), H2c-labels the timestamp labels (shipped).

- **H2c-1 · The coarse levels in one workgroup** (C, M). Two V-cycles of two sweeps each way per level and sixteen at the coarsest (`MG_CYCLES`, `MG_SWEEPS`, `MG_COARSE_SWEEPS` in `src/gpu/fluid/constants.ts`), 442 projection dispatches a projection at 512² *(read)*, 172 to 216 of them on levels of 256 cells or fewer, 32 of those the sixteen coarsest sweeps on a 4² or 6² grid where a dispatch is nearly all overhead. Solve every level of 32² or less in one single-workgroup dispatch (b and p are 8 KB of workgroup memory), `workgroupBarrier` between sweeps, in a kernel beside the multigrid's in `src/gpu/wgsl/fluid/`, driven from `vcycle` in `src/gpu/fluid/passes.ts`. **Pass:** dispatches a step at least 35 % under what `npm run encode` prints on main the day you start (it printed 267 at 512² on a thin gap on 2026-10-24; the 2026-09-28 estimate was about 256 fewer of 485), *and* `pressureSelfTest`'s residual after the projection no worse than 1.05 times main's, both printed, *and* `stages`' projection median no higher. **Check:** `encode` and `stages` exist; the residual line and this item's dispatch line are written (2026-11-01, `scripts/encode-solve.mjs`): `npm run encode -- --owed=h2c1` prints main's 269 dispatches a step and the thin gap's residual 6.393e-2, the open plate's 2.071e-3, held at 1.05 times; take `h2c1` out of `--owed` in `scripts/checks.json` when it passes. **Phone:** none (solver only).
- **H2c-3 · `mgZero` folded into the first sweep** (C, S). The multigrid zeroes each level's pressure with its own dispatch (`mgZero`, `fluid/core.ts:710`, `passes.ts:425`) before the first sweep reads it as a guess of zero. Make the first sweep of a level read zero instead of a buffer (a `first` flag in the kernel's argument), and drop the dispatch. **Pass:** 28 fewer dispatches a step *(read)*, the residual unchanged to the printed digit. **Check:** `encode`: the line "no mgZero dispatch" (44 a step on main) and the residual lines, written 2026-11-01; take `h2c3` out of `--owed`. Do it before H2c-1 if both are open: H2c-1 removes the levels this touches.
- **H2c-2 · A warm start and one V-cycle** (C, M, after H2c-1 and H2c-3). Start each projection's pressure from the last step's (the plate changes little in a sixtieth of a second) and run one V-cycle, not two (`MG_CYCLES`): about 218 fewer dispatches *(read)*. The warm start is `docs/evaluation-2026-09.md`'s. It is a physics change in the sense that the projection must stay as incompressible as before: **Pass:** `pressureSelfTest`'s residual no worse than 1.5 times main's after one cycle, *and* `npm run physics` and `npm run finite` unchanged, *and* the dispatches a step down by at least 150 against `encode` on main. Judge by the residual, not by eye. **Check:** `encode`, `physics`, `finite` exist; written 2026-11-01: one V-cycle a projection (2 on main, thin and open) and at most 119 dispatches a step, the residual bar 1.5 times main's once `h2c2` is out of `--owed` (the line switches by itself; nobody moves it). This is a Claude brief first (the residual bar is Claude's to pin, per the split).
- ~~**H2c-9 · Pack only after a step**~~ (**shipped**, 2026-11-26, 19ak-24a) (C, S, with 14j). `packDye` and `packVel` also ran on frames the solver did not step, half of all frames at 120 Hz. Skip both when no step ran since the last pack and nothing was drawn into the fields (`WebGPUFluid.fieldWrites`, skipping unchanged layers and empty `pack` passes in `WebGPUPlate.draw`); `h2c9` out of `--owed` in `scripts/checks.json` (`npm run framereads` 18/18: 30 frames packed with 30 dispatches against 60 and 240 on main). **Phone:** none. Rides with 14j's draw cap (14-show-at-the-gig.md §14j); this is the part that stays after the cap.

## The desk and the phone (lane B, S each unless marked)

Every entry here ships its phone version in the same PR, built on `src/components/phone/`, with `npm run phone`, `desk` and `panel` green.

- **5-looklink · The look link** (B, S). The text is in `docs/plan/05-playing-it.md` ("Look link"): the whole settings state in a URL, to show someone a look right now; opening one sets the look only (the projector window, the remote and the show server untouched). Build: a "Copy look link" on the desk and in the phone's Looks sheet that encodes the settings (through `sanitizePatch`, never trusted raw: `npm run sanitize`) as a fragment, and a loader that reads `#look=…` once at boot, applies it as a Go with no fade, and clears the fragment. **Pass:** a round trip over every built-in look (`PRESETS.length` of them, printed): encode → open → settings equal to the look's, all of them; a malformed or hostile fragment (truncated, 10 KB, a key that is not a setting) applies nothing and shows a notice, 0 settings changed; a link under 2,000 characters for every built-in look (the limit chat apps keep). **Check:** `npm run saves` and `sanitize` exist; the round-trip line is *owed* (a new `looklink` entry in `scripts/checks.json`, Claude). **Phone:** the same button in the Looks sheet; opening on the phone works from a texted link.
- **5-learncast · Learned mappings reach a network display** (B, S). Sound learn's triggers reach a Cast or network display; its learned *mappings* (a band bound to a setting) do not (`src/lib/soundLearn.ts`, `castProtocol.ts`). Carry the mappings in the cast state once (not every state: the lesson of S0's logo in `docs/stability-plan.md`) and apply them on the receiver. **Pass:** a receiver with a mapping learned on the laptop moves the bound setting with the band, a setting writer's value within 0.01 of the laptop's on 20 frames of a synthesised band, and the cast state's size without a mapping unchanged byte for byte. **Check:** `npm run learn` and `phonelink` exist; the cast line is *owed*. **Phone:** the phone as a receiver (`?cast`) shows the mappings in its Sound sheet.
- **5-actions · "Press the big dish" and "drop the lead dye" as actions** (B, S). The two have no `MidiAction` (`src/lib/midi.ts`, the union starting at line 29), so sound learn and MIDI cannot fire them. Add `press-dish` (the Press tool's big stroke, the one the desk's button makes) and `drop-lead` (a drop of the first dye) to `MidiAction`, `ACTION_LABELS`, the action table the keyboard and ⌘K read, and the remote; decide with `triggerable` whether each is on a beat (both are). **Pass:** both bind from MIDI learn and from sound learn's Trigger list and fire exactly once per press, `npm run desk` 's action-coverage line (every `MidiAction` has a label, a phone control and a remote entry) green with the two added; `npm run panel` green. **Check:** `desk`, `panel`, `learn`; no new check needed. **Phone:** a pad each on the phone's Perform sheet.
- **11-back · Evolve re-anchors on Go and Back** (B, S). Evolve wanders around the look before: `fadeSettingsTo` (Go) and `revertLook` (Back) and the sequencer's stages do not move `driftAnchor` or drop `driftGlide` keys, so 1,496 of 1,560 preset-to-preset Gos pull a dial more than a quarter of its travel off the new look, or switch on a dial it had off (14u, `docs/plan/14-show-at-the-gig-2.md`; `src/lib/drift.ts`, `lookFade.ts`). Re-anchor at the end of a look fade, a Back and each stage's arrival. **Pass:** the node check over `driftLook` for the 1,560 pairs: 1,496 → 0 dials pulled past a quarter of their travel, and 0 dials switched on from off; `npm run evolve` and `evolving` unchanged. **Check:** `evolve`, `evolving` exist; the 1,560-pair line is *owed* (14u's measure, Claude writes it from the numbers above). **Phone:** none (same code).
- **11-pinch · The phone's pinch loses moves under load** (B, S, root cause first). `npm run phone`'s "spreading them zooms in by as much as they spread" read 1.40, 1.40 and 3.00 times of 3.40 in three of seven runs with `PW_WEBGPU=1` (and once in a cloud session at 1.40): the zoom follows the first of six finger moves and none after. Sending the move the once-a-frame throttle holds back at the lift did not stop it; the inference is that the touch listeners' cleanup drops the pinch (a plate rebuilt mid-pinch would do exactly this). Find which, with a log of the touch handlers' attach and cleanup around the pinch, then fix it. **Pass:** 30 of 30 runs read 3.40 ± 0.05 under `PW_WEBGPU=1 npm run phone`, and a plate rebuilt mid-pinch (device-loss injection) leaves the zoom following the fingers. **Check:** `phone` exists; the rebuilt-mid-pinch line is *owed* (Claude). The check is not loosened. If the cause is the plate rebuilding, the fix belongs to S16 (GPU rebuild keeps the film) and this entry closes with it.
- **16b-logo · The logo goes with the dimmer** (B, S). The logo stays up in a blackout on the wall and on the front plate's projector: it is laid over the dimmer (`finishLight`), as it always was on the wall (`docs/plan/16-many-plates.md`). A blackout is the house lights; the logo is the owner's mark and a setting can choose. Add `logoInBlackout` (default 1: today's look), 0 takes the logo down with the plate. **Pass:** the setting defaults to today's pixels (`npm run mixer` and `wall` unchanged at the default); at 0 a blackout reads max pixel 0 on the wall and the front projector (`npm run pixels` line for blackout); the setting reaches the desk's Settings, the phone and MIDI (the `setting-auditor` agent runs on the PR). **Check:** `mixer`, `pixels`; blackout-with-logo-off line *owed*. **Phone:** a toggle on the Mark sheet.
- **8-pictures · Pictures, not swatches, in the cue list** (B, S). The text is in `docs/plan/08-desk.md` ("pictures, not swatches"): ship `gallery.yml`'s preset photographs as thumbnails, Save Look keeps a still of the plate in the preset file, sent to a receiver once and not in every cast state. **Pass:** `npm run desk` and `npm run phone` find a picture on every built-in look's row (`PRESETS.length` of `PRESETS.length`) and on a saved look; the cast state's size unchanged byte for byte; the thumbnails total under 400 KB gzipped (bar proposed, the build's budget `npm run sizes` already guards the bundle; thumbnails ship as files under `public/`, precached by the service worker so they exist offline: `npm run sw`). **Check:** `desk`, `phone`, `sw`; the every-look line is *owed*. **Phone:** the Looks sheet, where rows are smallest, gains most.

## The recorder and the build (lane B, M each)

- **13-recmem · Record writes to disk as it records** (B, M, Claude only in the split; the spec is here so the work is bounded). Record keeps the whole take in memory until it stops (`src/hooks/useRecorder.ts`): fine for a song, risky for a set. In Chrome, write each chunk to a file through File System Access (`createWritable`) as `MediaRecorder` emits it; elsewhere keep the memory path. **Pass:** a 60 min take at the Pro bitrate holds at most 64 MB of the page's JS heap at its end (`performance.measureUserAgentSpecificMemory` or `process.memoryUsage` in the Mac app; printed), against the take's size today *(measured by the first run)*, and the saved file plays through (`npm run codecblip` decodes it). A refused file picker falls back to memory with a notice, 0 takes lost. **Check:** `codecblip` exists; the heap line and the nightly hour (S7) are *owed*. **Phone:** the phone's Record toggle shows the same notice.
- **19d-lazy · Load the panels when first opened** (B+E, M, after 1.7 and 14h's precache). The main route loads about 527 KB of script gzipped (1.68 MB raw): the App's chunk 236 KB, the engine's 186, React's 66; only the routes are lazy (`main.tsx`). `motion` is 42 KB of it for 53 simple uses in six components. Make the phone's stage, the guide, the recorder, the MIDI panel and controller surface, the designer and Settings load on first open, and replace `motion`'s simple uses with CSS transitions. **Pass:** the first-load script at most 360 KB gzipped (527 → 360 is the 167 KB the panels and `motion` hold; bar proposed), `npm run sizes` and `loadtime` print before and after; with the network off after precache, every panel still opens (`npm run sw`: load, go offline, open each panel); `startup`'s first step no later than main's. **Check:** `loadtime`, `sw`, `startup` exist; the offline-panels line is *owed* (Claude, with 14h-precache first: do not start before 14h ships, a lazy chunk missing at a venue with no internet is the risk). **Phone:** the phone's sheets are the lazy ones; `npm run phone` green.
